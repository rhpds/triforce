== What You Did

In this lab, you:

* Pulled the Red Hat AI Inference Server as a single container image
* Served an IBM Granite 2B model on a CPU -- no cluster, no cloud, no GPU
* Called the model using the standard OpenAI-compatible API
* Classified text, extracted entities, and answered questions -- all from `curl`

Everything you used -- the container image, the model, the API -- runs on any Linux machine with a container runtime. No cluster. No operator. No cloud account.

== The API Is the Constant

The `/v1/chat/completions` endpoint you called in this lab is the same API at every scale:

[cols="1,3",options="header"]
|===
| Scale | How It Works
| *001 (this lab)* | `podman run` on a single machine
| *101* | RHOAI deploys the same container as an InferenceService on OpenShift
| *201* | An agent calls the same API with tools and orchestration
| *301* | A semantic router fans requests across CPU and GPU models using the same API
|===

Nothing changes but the infrastructure underneath. Your prompts, your code, your integrations -- they all carry forward.

== Clean Up

Stop and remove the inference server container:

[source,bash,role="execute"]
----
podman stop inference-server && podman rm inference-server
----

== Next: 101 — Model Deployment on OpenShift

You have a model running in a container. That works for a single user, a single model, on a single machine. What happens when you need:

* Multiple models, each with different resource profiles
* Auto-scaling under load
* Model versioning and rollback
* A dashboard to manage it all

In 101, you take the same inference server container and deploy it on OpenShift with Red Hat OpenShift AI. The platform handles scaling, routing, and lifecycle management. The API your applications call is the same one you used here.

One container becomes a platform.
