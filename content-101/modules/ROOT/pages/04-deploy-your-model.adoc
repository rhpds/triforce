      -H "Content-Type: application/json" \

== Exercise 3: Multi-Model Pipeline

Production workloads rarely use one model. Build a two-stage pipeline: a fast model triages, a larger model handles complex cases.

[source,bash,role="execute",subs=attributes+]
----
TICKETS=(
  "My invoice shows a charge for a service I cancelled last month."
  "The dashboard won't load and I've tried three browsers, cleared cache, disabled VPN, and the error persists across all devices in our office."
  "How do I add a second user to my organization?"
  "Your platform saved us 200 hours last quarter. Thank you!"
  "I was charged twice and my bank flagged it as potential fraud. I need this resolved immediately before I dispute the charges."
)
EXPECTED=(billing technical account praise billing)

echo "=== Stage 1: Fast triage (granite-4-0-h-tiny-cpu) ==="
echo "=== Stage 2: Complex cases escalate to granite-3-2-8b-instruct-cpu ==="
echo ""

for i in $(seq 0 4); do
  # Stage 1: fast model
  S1_START=$(date +%s%3N)
  S1=$(curl -s -X POST {maas_url}/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer {litellm_api_key}" \
    -d "{\"model\": \"granite-4-0-h-tiny-cpu\", \"temperature\": 0.0, \"max_tokens\": 20, \"messages\": [{\"role\": \"user\", \"content\": \"Classify this support ticket as billing, technical, account, or praise. Also rate your confidence as HIGH or LOW. Format: CATEGORY|CONFIDENCE\n\nTicket: ${TICKETS[$i]}\"}]}")
  S1_END=$(date +%s%3N)
  S1_MS=$((S1_END - S1_START))
  S1_ANSWER=$(echo "$S1" | jq -r '.choices[0].message.content' | head -1)

  CONFIDENCE=$(echo "$S1_ANSWER" | grep -oi 'HIGH\|LOW' | head -1)

  if [ "$CONFIDENCE" = "LOW" ] || [ -z "$CONFIDENCE" ]; then
    # Stage 2: escalate to larger model
    S2_START=$(date +%s%3N)
    S2=$(curl -s -X POST {maas_url}/v1/chat/completions \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer {litellm_api_key}" \
      -d "{\"model\": \"granite-3-2-8b-instruct-cpu\", \"temperature\": 0.0, \"max_tokens\": 10, \"messages\": [{\"role\": \"user\", \"content\": \"Classify this support ticket into exactly one category: billing, technical, account, or praise. Respond with only the category name.\n\nTicket: ${TICKETS[$i]}\"}]}")
    S2_END=$(date +%s%3N)
    S2_MS=$((S2_END - S2_START))
    FINAL=$(echo "$S2" | jq -r '.choices[0].message.content' | tr '[:upper:]' '[:lower:]' | tr -d ' .')
    echo "Ticket $((i+1)): Stage1=${S1_MS}ms(LOW) -> Stage2=${S2_MS}ms -> $FINAL (expected: ${EXPECTED[$i]})"
  else
    FINAL=$(echo "$S1_ANSWER" | cut -d'|' -f1 | tr '[:upper:]' '[:lower:]' | tr -d ' .')
    echo "Ticket $((i+1)): Stage1=${S1_MS}ms(HIGH) -> $FINAL (expected: ${EXPECTED[$i]})"
  fi
done
----

== Learning Outcomes

* `temperature=0.0` and minimal `max_tokens` are essential for production classification
* MaaS handles scaling transparently -- latency under load is the metric that matters, not replica management
* Multi-model pipelines (fast triage + accurate escalation) reduce average latency while maintaining accuracy
* Intel Xeon 6 CPU inference at $0/token means you can run experiments, batch jobs, and production pipelines without API bills
* You now have a complete, data-backed deployment recommendation
